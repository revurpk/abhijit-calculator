Hindu Panchanga Calculator
A self-contained single-file web app — no server, no framework, no build step. All five panchanga elements (tithi, nakshatra, yoga, karana, vara) plus lunar masa, eclipse, moudhyam, festivals, and auspiciousness scores are computed live in your browser using JavaScript astronomical models. Results may differ from printed almanacs by minutes to a day depending on the element.

Panchanga Elements
All five angas on the Panchanga tab are evaluated at local sunrise for the selected date and location — the reference moment used by traditional printed almanacs. The calendar grid uses noon as a representative snapshot for quick browsing.
Tithi Moon−Sun elongation ÷ 12°
diff = nm(mlong − slong); tIdx = ⌊diff / 12⌋ → 0–29
0–14: Shukla Pratipada → Purnima  ·  15–29: Krishna Pratipada → Amavasya  ·  duration ~19–26 h
Nakshatra sidereal Moon ÷ 13°20′
nRaw = nm(mlong − ayan) / (360/27); nIdx = ⌊nRaw⌋; pada = ⌊(nRaw − nIdx)×4⌋ + 1
27 nakshatras × 4 padas = 108 navamshas  ·  average duration ~27 h 13 min
Yoga sidereal (Sun+Moon) sum ÷ 13°20′
yIdx = ⌊nm(slong + mlong − 2·ayan) / (360/27)⌋ % 27
27 yogas  ·  ayanamsha subtracted twice (once per body)  ·  duration ~12–26 h, advances faster than nakshatra
Karana Moon−Sun elongation ÷ 6° (½ tithi)
kIdx = ⌊diff / 6⌋ (0–59 per lunation)
11 types: 7 movable (Bava, Balava, Kaulava, Taitila, Garija, Vanija, Vishti) cycle from kIdx 1–56  ·  4 fixed at month boundaries (Kimstughna, Shakuni, Chatushpada, Naga)
Vara weekday from calendar date
vara = date.getDay() (0 = Sun … 6 = Sat)
Hindu vara is sunrise-to-sunrise; date.getDay() is correct for the Panchanga tab (which samples at sunrise) and for daytime hours. It may be off by one only for the narrow pre-sunrise window on the calendar grid.
Lunar Month (Masa) — Amanta System
A lunar month runs new-moon to new-moon and is named for the Sankranti (solar rashi entry) that falls within it. Let r₀ = Sun's sidereal rashi at the current new moon, r₁ = rashi at the next new moon.
r₀ vs r₁TypeNameSignificance
r₀ ≠ r₁Normal (or Nija)HM[r₁]Standard muhurtha rules apply
r₀ = r₁Adhika (intercalary)HM[r₂]Avoid new ventures; merit for religious acts
Nija = the regular month immediately following an adhika month. Adhika months occur ~every 2.5–3 years, when the Sun stays in one rashi across two consecutive new moons (near aphelion, ~July). 2026 has Adhika Jyeshtha (June).

Planetary Combustion (Moudhyam)
A planet is moudhya (combust) when its elongation from the Sun falls below the visibility threshold.
PlanetThresholdTraditional restrictionTypical duration
Venus (Śukra)< 10° from SunMarriages, engagements, auspicious ceremonies40–75 days per cycle (~585-day cycle)
Jupiter (Guru)< 11° from SunUpanayana, initiation, new learning20–30 days per year
Geocentric elongation computed via full inclination-corrected heliocentric → geocentric conversion (Meeus Ch. 31, Kepler's equation with 5 iterations). Accuracy ±3° → timing error ±3–5 days at period boundaries.
Sky Tab — Rashi & Divisional Charts
Two side-by-side South-Indian style Rashi charts at the chosen date & time for the selected location. The wall-clock entered is interpreted as the location's local time (DST-aware via LOC.iana), so the chart is consistent whether the user is physically at that location or viewing remotely.
Grahas plotted 9 + Lagna
Sun (Su), Moon (Mo), Mars (Ma), Mercury (Me), Jupiter (Ju), Venus (Ve), Saturn (Sa), Rahu (Ra), Ketu (Ke), Ascendant/Lagna (As). Retrograde planets are tagged R (Rahu/Ketu always; others computed by comparing longitude at J vs J + 0.5).
Lagna east-horizon ecliptic intersection
L_asc = atan2(cos(RAMC), −(sin(ε)·tan(φ) + cos(ε)·sin(RAMC)))
RAMC = Local Sidereal Time. atan2 signs are chosen to pick the rising intersection (east), not the setting one. Verified: at sunrise, Lagna ≈ Sun.
Divisional charts D-1 … D-27

Viewing guide where to actually look
A "weather permitting" panel converts each body's ecliptic position to altitude (above horizon) and azimuth (compass bearing N/NE/E/…/NW). Bodies below the horizon show their next rise time (within 24 h). Mercury/Venus within 10° of the Sun are flagged "lost in glare". The Sun's altitude is classified into day / civil / nautical / astronomical twilight / night. The Moon's current nakshatra is shown with its principal stars (e.g. Rohini → Aldebaran) and a pointer to where the Moon is in the sky — so the abstract nakshatra index becomes a visible target you can find.

Security & Privacy
Everything you see is computed in your browser. The app has no backend, makes no network requests after the initial page load, and stores nothing across sessions (no cookies, no localStorage, no telemetry). Your location, dates, and searches never leave this tab.
DefenceWhat it does
Content-Security-PolicyRestricts script/style/font/img sources. connect-src 'none' blocks any runtime exfiltration. frame-ancestors 'none' prevents clickjacking.
Subresource IntegrityTabler Icons CDN pinned to a SHA-384 hash — CDN compromise → browser refuses the file.
Referrer policyno-referrer globally, so font/icon requests do not leak the page URL.
HTML escapingAn esc() helper wraps every interpolation of LOC.name into HTML so a future code path that brings in untrusted location strings can't inject markup.
Input validationLat/lon range-checked; NaN/Infinity rejected. Date inputs verified before use. parseInt always with radix and finite-number guard.
GeolocationNot auto-requested on load (cold prompt is poor UX and often auto-denied). User clicks "Auto-detect" explicitly; 10 s timeout; error codes translated to readable messages. Coordinates never leave the browser.
Cache boundingAll caches soft-capped at 5000 entries; oldest 1000 dropped when exceeded.
Residual risks: inline event handlers prevent the strictest CSP variant (no 'unsafe-inline'); Google Fonts cannot be SRI-pinned because its CSS varies per user-agent. If you self-host, both concerns disappear.
